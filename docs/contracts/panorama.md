# Panorama: the display module's contract

Panorama arranges the displays. Hyprland applies the saved setups ITSELF, from a generated Lua file Lares owns, so a setup holds
from Hyprland's start and through a shell crash; the shell is the GUI. The plan and the user's 32 decisions are in
`docs/agent_added_files_and_folders/panorama/PLAN.md`, and the Hyprland facts the rules rest on in `FACTS.md` beside it (gate:
`tools/dev/panorama_hypr_facts.py`). The names below are fixed: every stream builds against them.

## 1. Records

**Output** (one display as Hyprland lists it; `FocusedScreen.outputs` builds it from `hyprctl -j monitors all`, the engine from
`hl.get_monitors({all=true})`):

| field | type | from `hyprctl -j monitors all` | from Lua `HL.Monitor` |
|---|---|---|---|
| `name` | string | `name` | `name` |
| `description`, `make`, `model`, `serial` | string | the same | `description`, `serial` (no make/model in Lua) |
| `id` | int | `id` | `id` |
| `enabled` | bool | `!disabled` | `enabled` |
| `width`, `height` | int | mode px | `width`, `height` |
| `refresh` | real | `refreshRate` | `refresh_rate` |
| `x`, `y` | int | `x`, `y` | `x`, `y` |
| `scale` | real | `scale` | `scale` |
| `transform` | int 0-7 | `transform` | `transform` |
| `mirrorOf` | string | the NAME of the monitor whose `id` is `mirrorOf` ("" for "none") (FACT F10) | the name of the monitor whose `mirrors` holds it (`mirrors` is listed on the source, FACT E1) |
| `physW`, `physH` | int mm | `physicalWidth/Height` | `physical_width/height` |
| `modes` | `[{w,h,r,preferred}]` | `availableModes` parsed ("2880x1620@120.00Hz"; preferred = the first) | `available_modes` |
| `backend`, `hdr`, `bt2020`, `vrrCapable` | | `hardwareDetails.*` | `hardware_details.*` |
| `vrr` | int | `vrr` (bool → 0/1) | `vrr_active` |
| `bitdepth` | int | from `currentFormat` (`2101010` → 10) | 0 (none in Lua; liveDiff skips it there) |
| `cm`, `sdrbrightness`, `sdrsaturation` | | `colorManagementPreset`, `sdrBrightness`, `sdrSaturation` | `cm` |
| `driver` | string | from DrmWatch's connector scan (i915 / nvidia / evdi), "" when unknown | "" |

Outputs named in `PanoramaModel.IGNORED` (`LARESLOCK-HOP`, the lock's hop; `FALLBACK`, Hyprland's own) never count anywhere.

**Spec** (what one output should be): `{ enabled, mode ("WxH@R" | "preferred"), position: [x, y] (compositor logical px),
scale (number | "auto"), transform (0-3, rotation only), mirror (STORED: bool, "mirrors the internal panel"; RESOLVED: "" or the
internal's connector name), vrr (0 off | 1 on | 2 fullscreen), bitdepth (8 | 10), cm ("srgb" | "wide" | "edid" | "hdr" |
"hdredid"), sdrbrightness, sdrsaturation }`.

**Display identity**: `PanoramaModel.identityOf`. It is the description, whitespace collapsed; `headless:<name>` for a headless
output; `port:<name>` for an empty description; `<desc> @<name>` for two present twins. The **set key** is the identities in BYTE
order joined by ` + ` (`setKeyOf`).

## 2. Files

| file | written by | read by |
|---|---|---|
| `~/.local/state/lares/panorama/setups.json` | the shell (PanoramaStore), atomically; `lares panorama-import` once | the shell |
| `~/.config/hypr/config/panorama.lua` | the shell (EngineLink) whenever the data or the engine version changes, and when the config loads it and it is not there (`EngineLink.fresh`: a clone of the user's config); the import once | Hyprland: `pcall(require, "config/panorama")` at start and reload, `dofile` by eval |
| `$XDG_RUNTIME_DIR/lares/panorama.json` | the engine, after every action (temp file, then rename) | the shell |
| `config/panorama.jsonc` | the user (tunables only) | PanoramaConfig |

**setups.json / the data** (version 1):
```json
{ "v": 1,
  "displays": { "<id>": { "label": "DisplayLink · ACME ULTRAWIDE", "custom": false, "internal": false, "port": "DVI-I-1", "placeholder": false } },
  "setups":   { "<setKey>": { "name": "Desk", "custom": true, "used": 1795255230, "outputs": { "<id>": SPEC } } },
  "split":    { "3": "<id>" } }
```
`label` and an auto `name` are rewritten while `custom` is false. `used` is unix seconds of the last Keep. `split` maps a
workspace ("1".."4") to a display identity. An import placeholder is a display `port:<connector>` with `placeholder: true`; it
takes the identity of the first real display seen on that port (`bindPlaceholders`).

**panorama.lua** is generated by ONE function in two languages, `tools/panorama/generate.py` (the import and the tests) and
EngineLink (the shell). Both are held to `tools/dev/panorama_cases.lua`'s generation case. The file is, in this order:
1. a header ("Generated by Lares Panorama. Do not edit: use the Panorama popup.", the engine version, the time);
2. `local PANORAMA_DATA_JSON = [=*[<setups.json, compact>]=*]` (the long-bracket level chosen so the text cannot close it);
3. the verbatim text of `tools/panorama/engine.lua`.

It is COPIED, never linked into a snapshot (the themectl law: snapshots move).

**panorama.json, the engine's state**: `{ "v": 1, "session": "<HYPRLAND_INSTANCE_SIGNATURE>", "serial": <int, +1 per write>,
"engine": <engine version>, "set": "<setKey>", "kind": "setup|grown|default", "name": "...", "specs": { "<name>": SPEC (resolved) },
"split": { "1": "<name>", ... }, "unknown": ["<id>"], "bound": [{ "from", "to" }], "deferred": ["3"],
"trial": { "token": "", "phase": "none|trying|shown|kept|reverted|failed", "verdict": "" | "failed:<name>:<field>" },
"log": ["<time> <line>", ... (last 20)] }`. A reader judges it by the session it names.

## 3. The engine (`tools/panorama/engine.lua`, Lua 5.5 inside Hyprland)

One global table `panorama`. Its state fields are set only when nil, and its handlers are trampolines registered once
(`if not panorama.hooked`), so a second `dofile` replaces the functions and registers nothing. A reload starts a fresh Lua
state (FACT F2), and the config run registers again. Every handler body runs under `pcall` and logs a failure (FACT F14: an
error aborts the rest of the chunk). Timers use `timeout >= 1` and live in the table.

| entry | what it does |
|---|---|
| file run | decode the data, register the catch-all `hl.monitor({ output = "", mode = "preferred", position = "auto", scale = "auto" })` (NORULE). If `hl.get_monitors({all=true})` lists outputs (eval, reload), `panorama.apply("load")`. |
| `monitor.added` | `apply("added:<name>")`, skipped for an ignored name. NOT every plug fires it: an output that comes up under a standing `disabled` rule is listed, off, with no event (FACT G4), so `apply` tells a plug by the list itself (below) |
| `monitor.removed` | It is skipped for an ignored name. Inside the handler an unplugged output is STILL LISTED, `enabled` false, like one switched off (FACT E2), so the handler does only **the safety rule**: when no other enabled output remains, the internal panel is re-enabled there. A 100 ms timer then tells the two apart: the name gone from the list is an unplug, which reverts a live trial at once. Then `apply("removed")`, which resets the rule of every name that has gone (below). |
| `workspace.active` | run a move that was deferred (FACT F7) once its workspace is no longer the one on show on the focused monitor. An entry Hyprland (or the user) already satisfied is cleared WITH its persistent rule: `setRule` runs there too, or the rule keeps naming the old monitor |
| `config.reloaded` | `apply("reloaded")`: a reload runs the user's own `hl.monitor` lines AFTER the file's run (FACT E4); liveDiff keeps it silent when nothing was undone |
| `panorama.apply(why)` | `bindPlaceholders`, then `resolve`. **Plugged and unplugged are read off the list** (`P.seen`: the names listed at the last apply; after a reload they come back from the state file when it is this session's, so Hyprland's start counts every display as plugged and a reload counts none). A name that is GONE has its rule reset to the catch-all values WITH `disabled = false, mirror = ""` (FACT F17; G3: a partial rule keeps a `disabled`). **A PLUGGED EXTERNAL TURNS ON** (the user's rule, 2026-11-23): when its stored setup says off, the setup in force is corrected, the display is named in the state's `on` (`[{ set, id }]`) and the service stores it; the entry is kept over every data load that still says off (`keepOn`) and is done once the data says on itself, so a later off is the user's again. The laptop's own panel keeps its off ("only external"). For each present output whose `liveDiff` is not "", send `hl.monitor(<complete rule>)` (FACT F1: a partial rule merges with stale fields), mirrors last. Then the split as persistent `hl.workspace_rule`s by connector name (FACT F6), with explicit `hl.dsp.workspace.move` for a present workspace on the wrong monitor, EXCEPT the active workspace of the focused monitor, which waits (`deferred`), and EXCEPT a workspace whose target is an output that is STILL A MIRROR when the outputs were read: the rule that ends a mirror lands after the call that sent it, and a move onto the mirror answers `Monitor not found` (a Lua warning, exit 0). Those workspaces wait and one 150 ms timer (`settle`, 12 tries at most) applies again once the rule has landed. **THE HAND-OVER** (`handOver`, FACTS G1 / G2): a new output is born on a workspace of Hyprland's own (id 5) and stays on it though 3 and 4 were brought over; once one of its own split workspaces is on it, the birth workspace of a NON-focused monitor is moved to another display when it holds no window -- the new display then shows its own workspace and Hyprland destroys the empty one, with no focus or pointer move. The workspace count is four from the plug on. Then write state and nudge. |
| `panorama.try(json, token)` | A trial of a candidate data: snapshot the data in force, apply the candidate, arm a guard timer of 45 s, and verify at +1500 ms (`verify`). A mismatch reverts at once (`trial.phase = "failed"`, `verdict = "failed:<what>"`). |
| `panorama.shown(token[, ms])` | re-arm the guard to `ms` (the shell sends panorama.jsonc keepSeconds + 2 s of grace; 17 s when not given) |
| `panorama.keep(token)` | cancel the guard; `trial.phase = "kept"`. The data stays the candidate until the shell rewrites the file. |
| `panorama.revert(token)` | re-apply the snapshot; `trial.phase = "reverted"` |
| `panorama.reload_data(json)` | replace the data (the shell after a Keep, or after binding a placeholder) and `apply("data")` |
| the nudge | `hl.dispatch(hl.dsp.event("lares-panorama," .. serial))`, which arrives on socket2 as `custom>>lares-panorama,<serial>` (FACT F8) |

The JS rules in `modules/panorama/data/PanoramaModel.js` and their Lua twins carry the same names, and both pass
`tools/dev/panorama_cases.json`.

## 4. The service (`modules/panorama/data/PanoramaService.qml`; the mock `PanoramaMock.qml` has the same surface)

Inputs: `live` (default false), `focusSource` (FocusedScreen; `focus` is FINAL on an Item), `drm` (DrmWatch), `silicon` (for `gpuModeName`), `notifier`
(DesktopNotifier; the keep toast finds the scheduler through NotificationBus), `ready` (unlocked and on the glass: the keep toast waits for it), `stateDir`, `runtimeDir`, `configPath`, `hyprDir`
(`~/.config/hypr`), `engineSource` (path of `tools/panorama/engine.lua` in the running tree), `popupOpen` (written by the host).

Read-only outputs:

| name | type | meaning |
|---|---|---|
| `displays` | var | the present outputs, each an Output plus `ident`, `label`, `internal`, `ddc: { capable, value, max, busy }`, `kind` (portKind) |
| `plan` | var | `resolve(outputs, data)` for the live set (resolved specs by NAME, split by name) |
| `setKey`, `setupName` | string | the live set and its setup's name ("" when none is saved) |
| `setupSaved` | bool | the live set has a saved setup |
| `setups` | var | `[{ key, name, custom, used, live: bool, labels: [string] }]`: the live set first, then by `used` |
| `staged` | var | `{ <name>: SPEC (mirror as bool) }` or null; the popup edits this. It lives through a trial (`applying`, `awaiting`) and is cleared by every end of one |
| `stagedSplit` | var | `{ "1".."4": <ident> }` (complete, seeded from the RESOLVED split, never from the store's partial one) or null |
| `dirty` | bool | staged differs from what is in force: a spec differs, or the staged split differs from the RESOLVED split (a chip already in force is no change) |
| `phase` | string | `idle`, `staged`, `applying`, `awaiting` (the keep toast is up), `keeping`, `reverting` (both transient: Keep and every revert end in `idle`) |
| `trial` | var | `{ token, deadlineMs, totalMs, verdict }` |
| `splitIdents` | var | ONE read for the workspace chips: workspace ("1".."4") -> display IDENTITY. The staged split while an edit is staged, else the one in force (`resolve`'s split by name, mapped to identities: complete for every workspace that has a place) |
| `diagnostics` | var | `PanoramaModel.diagnose(...)` |
| `identify` | string | the output NAME being identified ("" none); written through `setIdentify` |
| `panes` | int | enabled, non-mirroring outputs (the glyph) |
| `mirroring` | bool | an output mirrors the panel |
| `brightnessRev` | int | moves whenever any `brightnessOf` answer does: read it FIRST in a binding that calls `brightnessOf` |
| `engineState` | string | `active` (the file is required and the engine answered this session), `missing` (no `config/panorama` line or file: the popup is read-only and says `lares panorama-import`), `stale` (the file's engine version is older than the tree's; rewritten at once), `error` |
| `engineWhy` | string | words for the popup when not active |

Methods (each returns nothing unless noted):

| method | meaning |
|---|---|
| `stage()` | start a staged edit from what is in force (idempotent): the resolved specs, the resolved split, and the layout's RELATIONS (below) |
| `stageMove(name, x, y)` | a tile dropped at (x, y) logical px (the canvas has already resolved snapping). The relations are read again from the picture the drop leaves |
| `stageSpec(name, patch)` | merge `patch` (any SPEC fields) into the staged spec. A change of the tile's size (`mode`, `scale`, `transform`, `enabled`, `mirror`) re-places the layout from the relations (below). The last display on cannot be switched off; a mirror is of the laptop panel only, and only while it is on |
| `stageSplit(ws, ident)` | a pure toggle of ONE workspace: `ws` goes to `ident`; a click on the display it is already on gives it back to the internal display (else to the first other display that holds a workspace) |
| `stageReset()` | stage the DEFAULT arrangement of the live set as if it had never been seen (`resolve` over an empty store: specs and split), so the user can Apply or Discard it. Kept, it simply overwrites the stored setup. Refused while a trial runs |
| `discard()` | drop the staged edit |
| `apply() : bool` | send the staged data to the engine as a trial. The owner closes the popup (decision 32), and the keep toast is posted. False when nothing is staged, a trial is out or the engine is not active. The staged edit stays until the trial ends |
| `keep()` / `revert()` | the keep toast's buttons (a click only). Keep writes the store and clears the edit. EVERY revert (the toast's button, Escape, the timeout, the engine's own `failed` / `reverted`) clears the staged edit, its split and its relations, ends in `idle` and asks the compositor for a fresh read of the outputs: what the popup shows afterwards is what is in force, never a picture of what did not hold. The toast is the one place that says a revert happened |
| `renameSetup(key, name)` / `forgetSetup(key)` | forget is behind the popup's UndoDrainButton. A rename to "" gives the automatic name back (`custom` false) |
| `brightnessOf(name)` | `{ capable, value (0..1, -1 unknown), pending, reason }`. An external with DDC is capable; the internal panel is not yet (stream A3); `pending` while DDC has not looked or a read is out; `reason` is words when not capable |
| `setBrightness(name, v01)` | an external's brightness over DDC (live, not staged); nothing for a display that is not capable |
| `setIdentify(name)` | "" clears |
| `ddcSet(name, value)` | live, not staged (0-100) |
| `ddcNames()`, `ddcKey(name)`, `ddcBusy(name)`, `ddcForgive(name)` | the idle dim's (`modules/idle/DdcDim.qml`): the outputs with a DDC channel, the display's identity (make, model, serial), a call is out, one more try now for a remembered failure |
| `enableOutput(name)` | the "connected but off" action |
| `quick(kind)` | the never-seen toast's buttons: `mirror` \| `external` (laptop panel off). Each runs as a trial, with the keep toast |

Signals: `openRequested(name)`: the never-seen toast's "Arrange…"; the owner opens the popup with that tile selected.

**The staging rules** are ONE file, `modules/panorama/data/PanoramaStaging.js`, which PanoramaService and PanoramaMock both call, so the
mock cannot differ from the service where an edit is staged (round 2 found it differing exactly where the bugs were: the split's seed, what
Apply and a revert leave, a rename to ""). The probe `panorama_service_probe.sh` runs the same checks on both.
- **Relations.** `stage()` reads `PanoramaLayout.relationsOf(rects, internal)` from the pre-edit layout and `stageMove` again from the
  picture a drop leaves (an opaque map: name -> how the tile hangs on its neighbour). A size-changing `stageSpec` writes every position
  `PanoramaLayout.relayout(newRects, relations, internal)` returns and NEVER recomputes the relations, so a change and its undo (a scale
  and back, a quarter turn and back, off and on) leave the layout where it was.
- **The split.** `stage()` seeds `stagedSplit` from the resolved split by identity; `dirty` compares against that map. A kept edit stores
  only what differs from the defaults the engine would compute for the staged layout (`splitForStore`): an entry equal to its default is
  deleted, and when that would not reproduce the edit (a default that depends on which workspaces are held) the whole map is stored. The
  engine's `splitOf` reads a partial map the same way (`panorama_cases.json`: a stored `{1: external}`).
- **EngineLink's answers.** `hyprctl eval` answers `ok`, a Lua WARNING (`warning: ...`, exit 0: logged once as `LARES panorama engine
  warned:`, never an error) or `error: ...` / a non-zero exit (holds `error`). A failure is let go by the next call that works, or by the
  engine publishing a state with a higher serial than the one the failure was met on. (Round 2's "no detail popup until the shell
  restarts": the warning above, read as an error, latched `error`, the popup read-only and `apply()` refused; the revert was the last
  call, so nothing ever cleared it.)
- **"Disconnected" is told once the absence has held 400 ms** (`goneCheck`): a mirror change can drop an output from ONE read.

**The mock's controls** (PanoramaMock only, for the mockup and the probes):
- `scenario` (string) and `scenarios` (a list of `{ id, label }`): `laptop`, `desk` (+ DisplayLink ultrawide above), `projector`
  (+ HDMI projector, never seen), `three` (laptop + ultrawide + TV), `onlyExternal`, `mirror`, `integrated` (the HDMI note),
  `dlNoService`, `modeFails`;
- `plug(fixture)` and `unplug(name)` (fixture: `lg`, `tv`, `proj`, `port4k`, from `PanoramaScenarios.js`);
- `failNextTrial` (bool);
- `log` (a list of strings: what the mock engine did).

The mock runs PanoramaModel's rules as its engine (`PanoramaMockEngine.js`): plug, resolve, apply, trial, verify, keep or revert,
on a clock it can speed up (`timeScale`).

## 5. The popup (`modules/panorama/popup/PanoramaTabs.qml` over `PanoramaPopup.qml` and `modules/presets/PresetsPopup.qml`)

**The machine popup is `PanoramaTabs`** (round 2): the content the owner (`PanoramaBarOwner`) hands the engine, ONE popup with two tabs, `"displays"`
and `"presets"`, behind one glyph. The popup is the clock popup's pattern (`ClockPopupContent`) over the two drop-ins, which it mounts
unchanged in latched Loaders (a tab is built when first shown), each laid out at its own size and centred by hand in the box:
- Inputs: `service` (PanoramaService / mock), `presets` (PresetsService; null: an empty Presets tab), `appLookup`, `fontFamily`, `style`
  (PanoramaStyle), `presetsStyle`, `renderScale`, `motionRunning`, `currentTab`, `restTab`, `selected`, `eager`, `parked`, `prewarm`.
- `currentTab` is HELD BY THE OWNER and bound here (a `Binding`, RestoreNone, since the selector assigns it); the owner decides it at the click
  by SITUATION (`situationTab`: any display with `internal` false, or `service.mirroring`, gives `"displays"`, else `"presets"`);
  `openWith(name)` forces `"displays"`. `restTab` is that rule's answer for the NEXT open: `restImplicitWidth/Height` aim the open at its size.
- Size: `implicitWidth` = the tab's own (460 / 596, and 304 while no preset is saved); `implicitHeight` = the tab row (12 + 34) + the tab's own, one step per switch.
- Forwarded per active tab: `keyboardFocusRequest` (Displays "none", Presets its HoverArm-driven word), `handleEscape()` (Presets: menu, rename, a
  confirm; Displays: the detail), the secondary (`secondaryOpen`, `secondaryKey`, `secondarySide`, `secondaryAnchor` mapped into this content's
  frame -- its right edge at the tile's row --, `secondaryComponent`, `secondaryAnchorAt`, `secondaryWidthFrom`; closed on the Presets tab, and the
  selection is dropped when the tab is left), `recycle()` (no detail, no menu or rename left), and the swipe hold (`swipeGestureActive`,
  `gestureHoldWidth/Height`, `gestureWheel(ev)`: a sideways two-finger swipe switches the tab, a vertical one is left to what scrolls below).
- Signals: `closeRequested()` (Apply, or a preset load) and `presetLoadStarted()` (a load, emitted first: the owner asks the glyph's `deal()`).
- `sharedFlags.popupOpen` is true while the DISPLAYS tab is on show (the service's DDC detection and panel read follow it).
- Check: `tools/dev/panorama_tabs_probe.sh` (ARM=all).

### The Displays tab (`modules/panorama/popup/PanoramaPopup.qml`)

Hosted under the tab row it runs `headerless`: no title row (the tab selector stands there), the setup in force is a caption under the canvas.

It follows the drop-in contract (`docs/contracts/gooey_engine.md`): `service`, `fontFamily`, `style: PanoramaStyle`,
`implicitWidth/Height`, `parked`, `prewarm`, `handleEscape(): bool`, `keyboardFocusRequest: "none"`. Its secondary is the
aerial pattern: `secondaryOpen`, `secondarySide` (the left of the popup unless the screen is too narrow there and wider on the right; decided at
the open), `secondaryComponent`, `secondaryKey` (the selected output's name),
`secondaryAnchor`.
- The main body holds: the setup title (the caption, hosted), the canvas (`ArrangeCanvas`), the setups list, the hint rows, and the Apply bar.
- `selected` (an output name) is popup-local. A click on a tile selects it and opens the secondary `DisplaySettings` for it.
- Hovering a tile calls `service.setIdentify(name)` after ~250 ms, and leaving clears it.
- Apply: `service.apply()`, then `requestClose()` (the owner closes it).

## 6. The bar glyph (`modules/panorama/bar/PanoramaBarButton.qml`)

Its inputs are `panes` (1-3; "+" past three), `mirroring`, `hovered` and `hueOn` / `hueOff`. Windows are tiled on every screen that
carries no mark, at rest. It has `GlyphFlourish { group: "panorama"; decorative: true }`, which takes them away and deals them in again
(a mark dips and springs back, it never goes), and the panes spring in or out when `panes` changes, their windows with them. A click
toggles the popup. There is no key, no right-click and no swipe (decision 9).

## 7. Identify (`modules/panorama/screen/IdentifyCard.qml`)

An Item laid over a screen's `lares-bar` window while `service.identify === <that screen's name>`. It draws an accent ring at the
screen's edge and a centred name card (label, WxH@Hz, scale). It is a presence fade (160 ms), adds no window and no remap, and
is skipped while that window is frozen.

## 9. Cast (`tools/panorama/lares-cast`, `modules/panorama/data/CastService.qml`)

A cast streams ONE output to a Miracast sink through fluxcast (facts and the live spike: `docs/agent_added_files_and_folders/panorama/CAST.md`).
Panorama owns the display (create, rule, place, remove); the cast tool only streams it by name and never creates or removes an output.

### 9.1 The tool

| verb | does |
|---|---|
| `lares-cast scan [--seconds N] --json` | `{"devices":[{"id":"wfd:<MAC>","index","mac","name","protocol":"wfd","capable":bool,"note"}],"fluxcast":"0.3.0","shim":bool,"protocols":["wfd"(,"dlna")]}`; `capable` is "WFD capability data detected"; `note` joins fluxcast's remarks ("not advertising Wi-Fi Display", "already running its own group", "pairs by PIN only"); `dlna` only when the fluxcast interpreter (`/opt/fluxcast/venv/bin/python3` if executable, else `python3`) imports `upnpclient` |
| `lares-cast start --device wfd:<MAC> --monitor <output> [--res WxH] [--fps N=30] [--bitrate 8M] [--no-audio] [--audio-device X]` | a stream of JSON lines (below), in the foreground, until fluxcast ends or the tool gets TERM / INT |
| `lares-cast restore` | gives back a Wi-Fi profile a dead cast still holds (THE HOLD below); nothing without a record. CastService runs it at its start, `scan` does it too |
| `lares-cast doctor --json` | `{"fluxcast","shim","ffmpeg","p2p":bool,"checks":<fluxcast --doctor-json>}` |

`start` events, one object per line: `{"event":"state","state":"scanning|connecting|negotiating|streaming|stopping|ended"}` (never backwards within an attempt),
`{"event":"mode","width","height","fps"}` (from "Negotiated media mode: 1920x1080p30"), `{"event":"stats",...}` (once a second while it streams: THE FIGURES below),
`{"event":"lost"}` (a stream that was up is gone and may be made again: said at once, before the wait for the Wi-Fi; a `retry` or a `failed` follows),
`{"event":"hold","ok":bool,"why"}` (the Wi-Fi profile is held for this attempt, or why not), `{"event":"retry","n":N}` (a new attempt follows; states start again at scanning), `{"event":"failed","reason":"activation|capture|cancelled|link|peer-gone|tool","detail":<fluxcast's ERROR line>}`
and last `{"event":"ended","code":N}` (0 after a stop, 1 after a failure). A refusal is `{"event":"error","reason":"monitor|device|tool|usage|scan","detail":...}`, exit 2 (1 for `scan`).

- It waits up to 3 s (`LARES_CAST_MONITOR_WAIT`, poll 100 ms) for `xrandr --query` to list `--monitor` as connected (a just-created headless output reaches Xwayland a moment after Hyprland lists it), then refuses it with reason `monitor` (fluxcast validates against Xwayland's list; a headless output is there once the engine made it).
- fluxcast runs under `setpriv --pdeathsig TERM`, `setsid`, stdin `/dev/null`, `PYTHONUNBUFFERED=1` (its stdout is a pipe: lines end in `\n` or `\r`).
- THE SHIM: the tool puts a private dir with `ffmpeg` -> `tools/panorama/cast_ffmpeg_shim` first in fluxcast's PATH; it execs the next real `ffmpeg` in PATH. It drops `-thread_queue_size <n>` (`LARES_CAST_DROP=1`: fluxcast <= 0.3.0 passes it where ffmpeg 9 refuses it; decided by `fluxcast --version`, overridden by `LARES_CAST_SHIM=0|1`) and asks the SENDER (the run with an `rtp_mpegts` output) for its progress (`-progress <fifo>`, `LARES_CAST_PROGRESS`). The dir is removed at the end.
- THE FIGURES: one `stats` a beat (`LARES_CAST_BEAT`, 1 s), on the beat's grid from the moment the stream came up, all of them in one event; nothing before the stream is up, nothing between a lost link and the next stream. A key is there once its figure has been HAD in this cast (no source: no key, ever); a live figure not known right now is null. The tool's cost: ~0.1 % of a core.

  | key | what | from |
  |---|---|---|
  | `age` | s since the stream first came up in this cast | the clock |
  | `reconnects` | times the stream was made again in this cast | the tool |
  | `fps` | frames encoded and sent a second, over the last 3 s | ffmpeg `-progress` `frame` |
  | `dropped`, `repeated` | frames the sender's rate control left out / sent twice (none came in time), over the whole cast, never back | `drop_frames`, `dup_frames` |
  | `behindMs` | how much later the stream's newest moment comes out than at the best instant of this sender: grows when the encoder cannot keep up | `out_time_us` against the clock |
  | `kbps` | kbit/s handed to the Wi-Fi card (headers in, retransmissions out), over the last 3 s | the group interface's `statistics/tx_bytes` |
  | `rttMs` | mean round trip of the ICMP echoes of the last 3 s, one a second to the address the stream goes to ("RTP target"); a TV that answered none of the first ten is asked no more | a ping socket (no root) |
  | `signalDbm`, `linkMbps` | the TV's signal here, the rate the card sends at; every 5th beat | `iw dev <group> station dump` (a read: no scan) |

  NOT among them, because it would be untrue: the picture's way to the glass (the TV's own buffer tells nobody), what the TV lost (its RTCP reports go to a port ffmpeg holds and never reads), the Wi-Fi's retries and losses (`tx retries` / `tx failed`: iwlwifi marks every frame of an aggregate it reclaims as delivered).
- RETRY: pairing fails ~2 in 3 times with a Wi-Fi firmware crash that drops the normal link ~8 s. On an activation timeout the tool retries AT MOST ONCE, only after `nmcli -t -f DEVICE,STATE device` shows a Wi-Fi device (`wl*`) connected again (up to 20 s); otherwise it fails. Never a loop.
- THE HOLD: the Wi-Fi profile in force is locked to the access point it is on for the life of a cast (`nmcli connection modify --temporary ... 802-11-wireless.bssid`, then one `connection up`; never on disk, never while a `p2p-*` group interface exists), which stops background scans and roaming: an authentication beside a live group crashes the card's firmware. The record is `$XDG_RUNTIME_DIR/lares/cast-wifi.json`; the end of the cast takes the lock off first, then reconnects once. The user's own BSSID lock is left alone; a hold that cannot be taken is said (`hold` event) and the cast goes on.
- THE LINK WATCH: fluxcast sleeps for ever when the link dies. While streaming, the group interface gone for `LARES_CAST_LINK_GRACE` (1 s) is `link`; nothing sent for `LARES_CAST_STALL` (20 s) is `link` or, with the group standing, `peer-gone`; the TV's teardown ("Stopping RTP stream") is `peer-gone` after 5 s. `link` is tried again ONCE, like `activation`; a stream that held 60 s earns both again.
- THE LOG: `~/.local/state/lares/cast/cast.log` (the run before: `cast-prev.log`): fluxcast's whole transcript, every event but the figures (each tenth set of them), and at the end the cast in one line (`average held 754 s, reconnects 0, 29.9 fps, dropped 3, ...`).
- STOP: TERM or INT to the tool = INT to fluxcast, 5 s, then KILL of its process group; whatever is left in the group is TERMed after fluxcast exits; `stopping`, `ended` 0. A stop before streaming is no failure.
- `failed` reasons: `activation` (the NetworkManager activation timeout; retried once), `capture` (wf-recorder / ffmpeg died), `cancelled` (the sink refused), `peer-gone` (the sink ended a stream that was up), `tool` (anything else). A cancel on the TV and an unreachable one look alike to fluxcast: both are `activation`.

### 9.2 The service (`CastService`; `CastMock` has the same surface, scripted)

`live` (false: a host that forgets reaches nothing), `enabled`, `toolPath`, `scanSeconds` | `devices` (facts `{id, name, protocol, capable, note}`), `scanning`, `scanError`, `scanInfo` `{fluxcast, shim, protocols}`, `scan(): bool`
| `state` (`idle` `connecting` `negotiating` `streaming` `stopping` `failed`; the tool's scanning is `connecting`), `device`, `monitor`, `mode` (`{width,height,fps}` or null), `failure` (`{reason, detail}` or null), `retried`
| `stats` (the figures as CastParse.js `figures` keeps them: null, or `{age, reconnects, <the keys had>}`), `holdStats()`, `releaseStats()`: published once a beat ONLY while somebody holds them (CastStats.qml), null otherwise; a lost link and the end blank the live ones and leave the totals; a new cast to the same display keeps the keys with nothing in them
| `start(deviceId, monitorName, opts): bool` (opts: `res`, `fps`, `bitrate`, `audio: false`, `audioDevice`; refused while a cast or a scan runs or while not live), `stop()`, `clearFailure()` (failed -> idle)
| signals `started(deviceId, monitorName)` (the stream is up: first `streaming`), `ended(reason)` (exactly once per accepted start: `"stopped"`, `"failed"`, `"peer-gone"`), and `stateChanged`.

One `start()` is one run of the tool, never restarted (no backoff); the tool's own single retry shows as `retried`. A scan while casting, a cast while scanning and a second start are refused. After `ended` the state is `idle` (stopped) or `failed` (until `clearFailure()` or the next start).
The reading rules are `CastParse.js` (a pure reducer, shared with the mock; `tools/dev/cast_parse_cases.js`).
Checks: `tools/dev/cast_tool_probe.sh` (the tool against stub fluxcast / xrandr / nmcli / ffmpeg), `tools/dev/cast_service_probe.sh` (offscreen, stub tool), `node tools/dev/cast_parse_cases.js [--arms]`.

## 10. Casting from the Displays view (the engine's cast displays, `CastKeeper.qml`, the chip and the tile)

The user's call: found TVs appear as a PARKED CHIP beside the canvas; a click starts the cast and the TV becomes a NORMAL display tile (drag, scale, mode,
mirror). Default for a new TV: EXTEND, centred ABOVE the laptop. The whole feature is behind `panorama.jsonc` `"cast": false` (off until the user's own try).

### 10.1 A cast display is a headless output the ENGINE makes

| name | what |
|---|---|
| output | `LARES-CAST-<n>` (n from 1, the lowest free), a Hyprland headless output made by `hl.exec_cmd("hyprctl output create headless NAME")` (the compositor's child; it is listed a moment later and `monitor.added` applies the resolved setup) and removed by `hyprctl output remove NAME` |
| identity | `cast:<device id>` (e.g. `cast:wfd:02:AE:00:00:0A:01`), never `headless:<name>`: a setup is remembered PER TV. The Output record carries `castId` (the engine's name -> identity table; the service copies it from the state file's `cast.outputs`); `identityOf` returns it first |
| kind / label | `portKind` "cast", port word "Cast" (the service labels the display with the TV's name); never DDC (`neverDdc`, `brightnessTarget` kind "none") |
| default spec | a never-seen cast identity: enabled, mode `1920x1080@60`, scale 1, centred above the laptop (the existing `defaultPosition`: its foot on the laptop's top edge, on top of whatever stands in that column), not mirrored; its stored spec may carry `cast: { res, fps, bitrate, audio }` (the stream's quality; defaults 1920x1080 / 30 / "8M" / audio on) |
| workspaces | an external like any other: alone it takes 3 and 4. With real externals shown those pick first (one real: 3 to it, 4 to the cast); a stored split always wins |
| mirror | **A CAST THAT MIRRORS HAS NO OUTPUT** (2026-11-23). `spec.mirror` true on the cast identity is the KEEPER's to read (`mirrorWanted`): it asks the engine for no output and streams the INTERNAL one; switched on while a cast runs, the output is REMOVED between the stop and the start, switched off it is made again. A cast output that exists is never sent `disabled` nor `mirror` (`specOn` / `specMirror` in both twins: `liveDiff`, `ruleOf` / `luaRule`, `splitOf`), because an output that is off or mirrors cannot be removed (`hyprctl output remove`: "output not found", FACT G5) and one switched off in the handler of its own `monitor.added` is a `wl_output` born and gone in milliseconds: every client binding it dies (the 13:38:38 crash: hyprpaper, the browser, the terminals, the shell). The TV is then shown by a STAND-IN display record (`PanoramaStaging.castStandIn`, name `LARES-CAST-0`, `mirrorOf` the laptop, `standIn: true`), so the canvas, the detail and the set's key still know it |
| toasts / trial | a cast never raises the never-seen "connected" toast, the "disconnected" toast or a keep prompt: starting is the user's click, stopping is the revert. Other foreign headless outputs behave as ever |
| NOT in `IGNORED` | the names are real displays to the model while a cast runs |

Engine API (by `hyprctl eval`, EngineLink `castOpen` / `castClose` / `castKeep`; since engine version 2):

| call | does |
|---|---|
| `panorama.cast_open(identity)` | the output of this identity (idempotent: the same identity reuses its output); its name is in the state file's `cast.outputs` at once |
| `panorama.cast_close(name)` | remove the output; its rule goes back to the catch-all values when the removal lands (apply sees the name gone). THE REMOVAL IS LOOKED AT AGAIN (`castgone:<name>` timer, 5 tries): one that is still listed is removed again, and one that is off or a mirror (an older engine's, a hand's) is switched on first. A name that is not a cast output does nothing |
| `panorama.cast_keep(names_json)` | the names a live cast holds. The sweep: after a 5 s grace every `LARES-CAST-*` output not in the list is removed. Also run 5 s after the engine's own start (config run / reload) |

The table (name -> identity) and the kept names live in `$XDG_RUNTIME_DIR/lares/panorama-cast.json`, read back at a reload (a fresh Lua state), so a reload keeps a live cast's output. State file: `cast: { outputs: { name: identity }, keep: [names] }`.
A cast-named output with no table entry is NO DISPLAY to either reader (the engine's `read_outputs`, the service's `_withDrivers`): a leftover takes no workspace and no tile until the sweep has it. The safety rule of `monitor.removed` does not count a cast output as a screen that is on.
THE CRASH-SAFE RULE: the engine cannot see the stream, so a cast output nobody keeps is swept: the shell tells it `cast_keep([])` at its start (a restarted shell has no live cast) and after every end.

### 10.2 The service surface (PanoramaService and PanoramaMock, the same names)

`cast` (the CastService / CastMock; null = no casting; ShellServices hands it over) | `castEnabled` (config `"cast": true` AND `cast !== null` AND the engine active) | `castDevices` (the cast service's devices, `capable` flagged; `[]` while off) | `castState`, `castDevice`, `castFailure`, `castMode` (the cast service's) | `castPhase` (`idle` `opening` `starting` `streaming` `stopping` `restarting`), `castOutput` (the output's name), `castActiveDevice`, `castActive`, `castWorking` (it is being made or made again, the stream not up: from the click until it streams, has failed or was stopped; a lost link, a restart; also a cast something else started on the cast service; never with casting off), `castStats` / `castHoldStats()` / `castReleaseStats()` (the cast service's figures), `castNotice` (`{ device, text }` for 6 s after a cast that did not hold) | `castStatusText(deviceId)` ("Preparing…" "Connecting…" "Retrying…" "Negotiating…" "Casting" "Stopping…" "Restarting…") | `castNoticeFor(deviceId)` | `castNameOf(identity)` | `castStart(deviceId): bool` (a refusal leaves its reason as the device's notice; a start during the popup's scan is ACCEPTED and begins when the scan ends, "Waiting for the scan…") | `castDismissNotice()` | `castMirrored` (the cast has no output: it mirrors), `castDisplayName` (its output, or the stand-in), `castSetMirror(on)` (stores the TV's mirror and lets the keeper restart ONCE in the other shape: no trial, like the quality) | `castStop()` | `castQualityOf(name)` | `castApplyQuality(q)` (saves the quality in the setup's spec and restarts the stream ONCE) | `castKeeper`, `configObject` (for probes).

`CastKeeper` owns the ORDER of a cast (one per service). EXTENDED: `castStart` -> `openOutput(identity)` -> the output is LISTED and the resolved setup has LANDED (`liveDiff` of the plan against it says "") -> `keepNames([name])` -> `cast.start(device, name, quality from the spec's `cast`)` -> `started`. MIRRORED (`mirrorWanted(identity)`: the stored setup of the displays there are, with the TV's stand-in): no `openOutput` at all -> `cast.start(device, the internal output, quality)`; `virtual` is true. A RESTART (`restart`: the quality, the mirror) is one `cast.stop(true)` -- the tool keeps its Wi-Fi hold, SIGUSR1 -- and, at the end, `_enter()`: the shape now wanted is taken (to a mirror the output is closed, from a mirror it is opened and waited for) and the stream starts; `_finish` asks `cast.restore()` (`lares-cast restore --now`) so a hold no start took is given back. The stream's end (ANY reason) -> `closeOutput(name)` ONCE and `keepNames([])`, the layout falls back to the remaining set by the normal resolve; a failure leaves a notice for 6 s (activation "The TV did not answer", cancelled "Cancelled on the TV", peer-gone "The TV ended the stream", link "The Wi-Fi link to the TV broke", else "fluxcast failed: <detail, first 60 characters>", an output that never shows within 12 s "The display could not be made") and then clears the cast service's failure. A stop before the stream is up closes at once. A change of mirror while streaming restarts the stream ONCE in the other shape. Scan: `cast.scan()` when the view opens and casting is on, at most once per 30 s, never while casting.
There is no keep trial anywhere in a cast's start.

### 10.3 The popup

`CastChip` (one per capable device not being cast) sits in the parked row; the row's height `castRowHeight` is reserved while a device is listed, so the confirm step (the honest line "Pairing can fail and drop Wi-Fi for a few seconds." and **Cast**) opens in place with nothing moving. Leaving the chip or Escape puts it back. While it connects the chip shows the cast's words and the TV is no tile yet; once the stream is up the TV is a normal tile with a cast mark and its name and the chip is gone. Its detail (`DisplaySettings`) has a Cast block: the state line with the mode (the caption's note is how long it streams, and "reconnected once"), **Stop casting**, the stream's figures (`CastFigures`: two columns, built only for a cast display, it holds the figures while it exists; one that is not known right now is "–"), resolution / frame rate / bitrate / sound as a DRAFT until **Apply to stream**; no brightness, VRR, bit depth, colour or On; Mirror stays, and for a cast it acts at once (`castSetMirror`: no Apply, no keep toast); a detail open on the cast follows its display to its new name (`PanoramaPopup._castName`). A click on a chip that shows a notice dismisses it and opens the confirm step. With casting off nothing here exists (no chip, no scan, no engine call; the popup's picture is the same).

### 10.4 The bar's glyph while a cast is being made
